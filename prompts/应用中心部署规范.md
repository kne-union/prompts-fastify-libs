# 应用中心部署规范

适用于部署到应用中心（developer-document 内的 `@kne/fastify-app-manager`）的**全栈应用**（`@kne-template/fullstack-biz-app`）与**后端业务应用**（`@kne-template/fastify-app`）。新增 / 修改环境变量、调整包结构、打包上传、通过 MCP 部署时按本文执行。

## 部署包结构

zip 根目录直接包含：

```
package.json            # 根 package.json（name / version）
build/                  # 前端产物，须含 index.html、entry.html、entry-prod.html 之一
server/
  package.json          # 服务端依赖，应用中心会执行 npm install；禁止 file: / link: 本地依赖
  index.js              # 服务入口
  server.js
  env.schema.json       # 环境变量声明（必需）
  sql/*.sql             # 可选：迁移脚本，文件名只含 [A-Za-z0-9_-.]
```

不要打进包：`node_modules`、`.env*`、`.git`、`server/build`、日志、本地 sqlite 库（如 `server/data.db`）。用 `packApp` 打包会自动排除。

## 环境变量声明：server/env.schema.json

### 规则

- 服务端读取的**所有**环境变量（`fastify.config.*`）都必须在 `server/env.schema.json` 声明；新增变量时同步改这里，不要在 `server.js` 里内联 schema
- `server.js` 通过 `require` 引用同一份 schema：

```javascript
fastify.register(require('@fastify/env'), {
  schema: require('./env.schema.json'),
  dotenv: true
});
```

- 格式：JSON Schema，`type` 为 `"object"`，`properties` 每一项是对象；`required` 只能引用 `properties` 中声明的键
- 每个变量写 `description`（应用中心「环境变量」页与 MCP `get_app_env` 会展示给填写的人）
- 有合理默认值的写 `default`；`required` 只放**没有默认值且缺失就无法运行**的变量（如 OSS 密钥）
- 密码、密钥类变量加 `"writeOnly": true`，应用中心按密钥脱敏展示
- 可用关键字：`type`、`default`、`description`、`title`、`enum`、`pattern`、`minLength`/`maxLength`、`minimum`/`maximum`、`writeOnly`、`separator`（`@fastify/env` 扩展）；其它未知关键字会导致校验器编译失败
- 数字类变量写 `"type": "number"`（值来自字符串，会自动转换）；空字符串视为未配置

### 示例

```json
{
  "type": "object",
  "required": ["OSS_BUCKET", "OSS_ACCESS_KEY_SECRET"],
  "properties": {
    "PORT": { "type": "number", "default": 8040, "description": "服务端口；部署到应用中心时由应用中心分配" },
    "DB_DIALECT": { "type": "string", "default": "sqlite", "description": "数据库类型，如 sqlite、mysql、postgres" },
    "DB_PASSWORD": { "type": "string", "writeOnly": true, "description": "数据库密码" },
    "ENV": { "type": "string", "default": "local", "description": "运行环境：staging 使用 entry.html，prod 使用 entry-prod.html，其它使用 index.html" },
    "OSS_BUCKET": { "type": "string", "description": "OSS Bucket 名称" },
    "OSS_ACCESS_KEY_SECRET": { "type": "string", "writeOnly": true, "description": "OSS AccessKey Secret" }
  }
}
```

### 应用中心注入的变量

以下变量由应用中心在启动时注入，仍应在 schema 中声明（本地开发需要默认值），但**不会**出现在应用中心的环境变量列表里，也不需要用户填写：

- `PORT`
- 数据库连接 `DB_*` 与 `DB_TABLE_PREFIX`：默认使用应用中心托管库；需要专属库时在应用中心「数据」页配置，不在环境变量页填写
- 统一登录相关：`AUTH_MODE`、`OIDC_*`；`ORIGIN` 未配置时也会注入

### 校验时机

| 时机 | 行为 |
|------|------|
| 上传版本 | 缺少 `server/env.schema.json`、JSON 非法或不符合上述格式 → 拒绝上传 |
| 部署 | 「校验环境变量」阶段按该版本 schema 校验合并后的变量；不通过则停止，不切换版本、不执行迁移、不启动 |
| 启动 / 重启 | 同样先校验；不通过直接报错，不影响正在运行的进程 |

错误信息形如 `环境变量不符合 env.schema.json：OSS_BUCKET 必填，未配置；PORT 类型应为 number`。在应用中心「环境变量」页（或 MCP `save_app_env`）补齐后重新部署 / 启动。

## 打包与上传

在应用根目录（先完成前端构建）：

```bash
# 检查 + 打包，输出 zip 路径
npx @kne/npm-tools packApp

# 检查 + 打包 + 上传，输出 fileId（需先 initDevDocumentMcp，令牌所属用户为管理员，应用已在应用中心创建）
npx @kne/npm-tools packApp --upload --name <应用 name>
```

`packApp` 会先检查：根 `package.json`、`build/` 入口文件、`server/package.json`（无本地依赖）、`server/index.js`、`server/env.schema.json` 格式、SQL 文件名；任何一项不通过都不会打包。`--version` 默认取根 `package.json` 的 `version`，同一应用内版本号不能重复。

## 通过 MCP 部署（developer-document，管理员令牌）

1. `list_apps` / `get_app` 确认应用存在；没有则 `create_app`
2. `packApp --upload` 得到 `fileId` → `upload_app_version { name, version, fileId }`
3. `get_app_env { name, versionId }` 查看声明变量与问题 → `save_app_env` 补齐（密钥保持 `********` 表示不改）
4. 有 SQL 时 `list_app_migrations` 确认待执行脚本
5. `deploy_app { name, version }`，默认等待并返回各阶段结果
6. 失败时：`get_app_logs { name, stream: "err", keyword }` 看错误日志；`list_app_tables` / `list_app_rows` / `query_app_sql`（只读）排查数据；`get_app_load` 看 CPU / 内存 / 请求负载

## 禁止

- 在 `server.js` 内联环境变量 schema，或读取未在 `env.schema.json` 声明的变量
- 把可默认的变量放进 `required`，或给密钥类变量写真实默认值
- 部署包包含 `.env`、`node_modules`、本地数据库文件，或 `server/package.json` 使用 `file:` / `link:` 依赖
- 跳过 `packApp` 检查手工打 zip 上传
